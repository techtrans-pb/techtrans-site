# TriTrans LP本文ドラフト v0.3｜商品開発側レビュー結果

**作成日**：2026-10-09  
**対象資料**：TriTrans LP本文ドラフト v0.3  
**レビュー担当**：TriTrans教育事業開発  
**引継ぎ先**：TriTransヘッドクオーター（HQ）  
**レビュー観点**：AI実務活用教育の商品実態、価格、対象、実施条件、カリキュラム、個社導入コースとオーダーメイド研修の境界、経営者向けAI実務体験との整合、将来の商品拡張性、厚生労働省の事業展開等リスキリング支援コースを意識した公開情報設計の自然さ

---

# 1. 総合判定

LP v0.3のAI実務活用教育パートは、**公開可能な設計にかなり近い**。

現行商品との主要整合点は以下の通り。

- AI実務活用研修｜個社導入コース
  - 3時間×5回
  - 計15時間
  - 2名から実施
  - 最大10名
  - 2名 900,000円（税抜）
  - 3名 1,200,000円（税抜）
  - 4名以降 1名追加ごとに300,000円（税抜）
  - 事前面談
  - 会社別ゴール
  - 受講者ごとの実務テーマ
  - OFF-JT形式
- 経営者向けAI実務体験
  - 1日3時間 90,000円（税抜）
  - 2日 3時間×2回 150,000円（税抜）

また、LP上で助成金を営業訴求に使わず、
- 商品内容
- 標準時間
- 標準価格
- 受講人数
- 実施形式
- 教育目的
- 受講の流れ

を明示している点は、**制度確認に耐えやすい情報設計でありながら、通常の商品説明としても不自然ではない**。

商品開発側としての主要修正推奨は以下。

1. **個社導入コースとオーダーメイド研修の境界を明確にする**
2. **「各職種の仕事をAIで改善する技能」という表現を少しだけ商品実態に寄せる**
3. **個社導入コースで会社に残る成果をもう少し具体化する**
4. **経営者向けAI実務体験が必須ステップに見えないよう補足する**

HQ判断に戻すべき主要事項は、

- オーダーメイド研修をLP上でどこまで前面に出すか
- 経営者向けAI実務体験のコピー強度

の2点。

# 2. 修正事項①｜個社導入コースとオーダーメイド研修の境界

## 1. 問題箇所

オーダーメイド研修について、

> その他、企業様の業務内容・対象者・目的に応じたオーダーメイド研修も承ります。

とし、

- 特定部門向けのAI実務研修
- 管理部門・営業部門向けの職種別研修
- 新規事業・企画部門向け研修
- 既にAIを使っている社員向けの実務高度化研修
- 社内ルール・安全利用と組み合わせた研修
- 少人数の集中研修

等を例示している。

## 2. 理由

現行の個社導入コース自体がすでに、

- 会社別ゴール
- 受講者ごとの実務テーマ
- 職務に応じた題材

を組み込む商品である。

このため、現状のLPでは、

> 個社導入コースも会社別に設計  
> オーダーメイド研修も会社別に設計

となり、両者の差が分かりにくい。

将来的に、

> 「90万円の個社導入コースではなく、短いオーダーメイドで」

という価格・範囲のカニバリを誘発する可能性がある。

## 3. 修正案

オーダーメイド研修は、**標準の個社導入コースでは対象・時間・テーマが合わない場合の例外商品**として整理する。

推奨文案：

> **標準の個社導入コースでは対象・時間・テーマが合わない場合に、目的を限定した個別研修もご相談いただけます。**

例示も、

- 特定テーマに絞った短時間研修
- 既にAIを利用している方向けの高度化研修
- 特定部門のみを対象とした研修

程度に絞る。

「管理部門向け」「営業部門向け」は個社導入コースでも十分対応可能なため、オーダーメイド固有例としては出さない方がよい。

## 4. HQへ戻すべき判断事項

**あり。**

HQ判断事項：

- オーダーメイド研修を正式商品としてどこまで前面に出すか
- 個社導入コースとの価格・範囲境界
- 短時間研修の最低価格
- LP上で「個別見積」とだけ見せるか
- 例外商品として控えめに見せるか

# 3. 修正事項②｜「各職種の仕事をAIで改善する技能」の表現

## 1. 問題箇所

AI実務活用教育の説明で、

> **各職種の仕事をAIで改善する技能を身につけるための教育です。**

としている。

また、

> その職務で多くの企業に共通する業務・作業を題材に、生成AIを活用する技術を学びます。

と記載している。

## 2. 理由

方向性は正しい。

ただし「各職種の仕事をAIで改善する技能」まで言い切ると、現時点の商品実態より広く読まれる可能性がある。

現行商品の中心は、

- 生成AI
- 文書
- 音声
- 既存資料
- 調査
- 情報整理
- 提案
- 企画
- 品質確認
- 安全利用

等。

一方、

- 製造現場の高度な画像判定
- 生産計画最適化
- システム実装
- AIツール開発

等は、教育ではなくB｜AI導入・業務改善支援、C｜AIシステム・ツール受託開発へ越境する場合がある。

そのため、教育商品の責任範囲を適切に見せる必要がある。

## 3. 修正案

推奨案1：

> **各職種の実務で、生成AIを安全かつ効果的に活用する技能を身につける教育です。**

推奨案2：

> **受講者の職務に近い業務を題材に、生成AIを実務で使う技能を身につけます。**

「仕事をAIで改善する」より「生成AIを実務で使う」とした方が、教育商品の責任範囲が明確。

## 4. HQへ戻すべき判断事項

**軽微にあり。**

「改善」という言葉をブランド上どこまで強く出すかはHQ判断。

商品開発側としては、責任範囲を明確にするため上記修正を推奨。

# 4. 修正事項③｜個社導入コースの成果物・残置価値

## 1. 問題箇所

受講後に会社へ残るものとして、

- AIを安全に使える人材
- 自社で試すAI活用テーマ
- 利用上の注意点・確認手順
- AI活用を継続するための考え方

を記載している。

## 2. 理由

思想としては正しいが、90万円の商品説明としてはやや抽象的。

現行の商品設計では、

- AI活用マップ
- 安全ルール
- 90日計画
- 最終報告
- 受講者ごとの実務成果物

等、もう少し具体的な残置物を想定している。

LP上ですべて固定表示する必要はないが、

> **受講後に会社へ何かが残る商品**

であることをもう少し具体的に見せてもよい。

## 3. 修正案

例：

> 受講後には、受講者の実務成果に加え、今後試すAI活用テーマ、利用上の注意点・確認手順、継続活用のための整理資料を会社に残します。

なお、標準成果物名が完全確定する前に、

- AI活用マップ
- 90日計画
- 最終報告

等をLPへ固定しすぎない方がよい。

## 4. HQへ戻すべき判断事項

**なし。**

教育事業開発側で標準成果物を確定した後、LPへ反映可能。

---

# 5. 修正事項④｜経営者向けAI実務体験との整合

## 1. 問題箇所

経営者向けAI実務体験のコピー：

> **AIを社員に任せる前に、まず経営者から。**

## 2. 理由

商品コピーとしては強く、既存パンフレットとも整合している。

ただし実際の商品戦略では、

- 必ず経営者が先に受ける必要はない
- 経営者は構想を出す
- 社員がAIを実務で使う
- TriTransが技術・業務へ翻訳する

という役割分担が成立する顧客もある。

したがってLP全体で見ると、

> 「経営者が先に受けることが正解」

と一般化して読まれる可能性は避けたい。

## 3. 修正案

メインコピーは残してよい。

その下に、

> **経営者ご自身がAIの手応えと限界を知りたい場合に、短時間で実務体験いただくコースです。**

等を追加し、

> 必須ステップではなく、経営者本人向けの選択肢

であることを明確化する。

## 4. HQへ戻すべき判断事項

**あり。**

これは商品仕様ではなく、

- 営業導線
- ブランドコピー
- 経営者向け商品の見せ方

に関する判断なのでHQ領域。

# 6. OFF-JT表記について

## 1. 問題箇所

個社導入コースで、

> 通常業務と区別したOFF-JT形式で、3時間×5回、計15時間実施します。

と記載している。

## 2. 理由

商品開発側としては、**不自然ではなく、残してよい**と判断する。

OFF-JTであることは、

- 研修商品の実施条件
- 通常業務との区別
- 受講者が学習に集中する環境

を説明する通常の商品情報でもある。

助成制度を意識していることが露骨に見える表現ではない。

## 3. 修正案

**修正不要。**

ただし今後も、

> 助成対象となるためOFF-JTです  
> 支給要件を満たすため15時間です

等の書き方はしない。

現行の、

> 通常業務と区別したOFF-JT形式

で十分。

## 4. HQへ戻すべき判断事項

なし。

# 7. 助成制度を意識した公開情報設計について

## 1. 問題箇所

LPでは、

- 15時間
- OFF-JT
- 対象人数
- 料金
- 事前面談
- 受講者ごとの実務テーマ
- カリキュラム
- 受講の流れ

等を具体的に記載している。

## 2. 理由

これらは助成制度対応のためだけに付けた不自然な情報には見えない。

むしろ90万円の法人研修商品として、

- 何をするのか
- 誰が受けるのか
- 何時間なのか
- いくらなのか
- どう進めるのか

を公開するのは自然。

また、制度確認上も、

- 教育目的
- 対象
- 標準時間
- 標準価格
- 実施方法

が明確である方が整合確認しやすい。

## 3. 修正案

基本方針は現状維持。

LPでは助成金名を営業訴求に使わない。

必要ならFAQ等で、

> 公的支援制度の利用を検討される場合は、適用可否や申請条件を個別にご確認ください。

程度に留める。

ただし、この一文も必須ではない。

## 4. HQへ戻すべき判断事項

**あり。**

- 制度名をLPへ一切載せない
- FAQのみ触れる
- 問い合わせ後に個別案内する

のどれにするかはHQ判断。

商品開発側としては、

> **現時点では制度名をLPへ出さなくてよい**

と考える。

# 8. 事業展開等リスキリング支援コースへの寄せすぎ防止

## 1. 問題箇所

現行LPに明確な問題はない。

ただし今後の改稿で注意が必要。

## 2. 理由

TriTransの商品設計は、

> 顧客業務に必要な教育を作る

ことが先。

制度要件に合わせるために、

- 教育目的
- カリキュラム
- 時間
- 対象者

を作るものではない。

したがって、

- DX人材育成
- リスキリング
- 新規事業対応
- 助成対象

等の制度寄り表現を前面に出しすぎると、

> **商品本来の「実務活用教育」**

が歪む。

## 3. 修正案

今のLPの主軸、

> **顧客業務から教育内容を考える**

を維持。

制度対応は裏側で、

- 実施計画書
- カリキュラム
- 標準時間
- 講師要件
- 価格根拠
- 証跡
- 受講記録

等を整備する。

## 4. HQへ戻すべき判断事項

なし。

教育事業開発側の基本運用ルールとして保持する。

# 9. 将来の商品拡張性

## 1. 問題箇所

現行LPでは、

- 事務
- 営業
- 新規事業
- 管理部門
- 高度化

等へ広げられる構成になっている。

## 2. 理由

将来的には、

- 営業職向け
- 管理部門向け
- 新規事業向け
- 経営者向け
- eラーニング＋対面
- 高度化研修

等へ展開できる良い構造。

一方で、現時点で職種別コースをすべて正式商品として出す必要はない。

実績・教材・運営標準が固まる前にSKUを増やすと、

> 商品数だけ増え、標準化が追いつかない

状態になりやすい。

## 3. 修正案

LPでは当面、

- AI実務活用研修｜個社導入コース
- 経営者向けAI実務体験
- その他個別研修

の3層で十分。

職種別コースは、複数案件で再現性が確認できた段階で独立商品化を検討する。

## 4. HQへ戻すべき判断事項

**将来あり。**

職種別商品を正式商品化する段階でHQ判断。

# 10. 商品開発側の最終推奨

公開前に優先して直すべき点は、実質以下の2点。

## 必須度：高

### ① オーダーメイド研修の位置づけ整理

> 個社導入コースの安価な代替商品に見せない。

### ② AI実務活用教育の表現を少し商品実態へ寄せる

現行：

> 各職種の仕事をAIで改善する技能

推奨：

> 各職種の実務で、生成AIを安全かつ効果的に活用する技能

# 12. 結論

LP v0.3のAI実務活用教育部分は、

- 商品実態
- 価格
- 実施条件
- 対象
- カリキュラム
- 受講後の状態
- 経営者向けコースとの関係

の面で、全体として大きな矛盾はない。

> **助成制度に商品を寄せるのではなく、商品を正しく説明した結果として制度確認にも耐えられる情報になっている**

今後も、

> **商品設計は顧客業務起点**  
> **制度対応は裏側の運用設計**

という順序を崩さない。

以上。
