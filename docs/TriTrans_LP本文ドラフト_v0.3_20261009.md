# 2. こんな相談から始まります

AIについて相談したい。  
でも、何を頼めばよいのかは、まだ決まっていない。

それで構いません。

- 社員がAIを使い始めたが、使い方に差がある
- AIを仕事で使いたいが、どこから始めればよいか分からない
- 今の使い方が本当に効率化につながっているか確認したい
- 特定の業務をAIで改善できるか試したい
- AIを仕組みに組み込みたい
- AIで作った資料を、そのまま外に出してよいか不安
- 研修、業務改善、開発のどれが合うのか分からない

**最初に商品を決めるのではなく、御社の業務を見て、最も効果の出る方法を一緒に考えます。**

# 5. AI実務活用教育

## AIの使い方を教える講座ではなく、各職種の仕事をAIで改善する技能を身につける講座。

TriTransのAI実務活用教育では、  
AIツールの操作方法やプロンプトの型だけを学ぶのではありません。

事務、営業、新規事業など、受講者が実際に担当する職務に合わせて、  
**その職務で多くの企業に共通する業務・作業を題材に、生成AIを活用する技術を学びます。**

事務職であれば、文書作成、集計、確認、情報整理。  
営業職であれば、ニーズ整理、議事録、提案書作成。  
新規事業であれば、調査、比較、仮説整理、企画作成。

こうした職務に直接関係する業務でAIを使い、  
作業時間を短縮しながら、確認・修正を通じて成果物の品質を高める技術を身につけます。

# 6. AI実務活用研修｜個社導入コース

## AIを学ぶ研修ではなく、御社でAIを使い始めるための15時間講座。

### 研修前に、会社と受講者の仕事を確認します

研修前に経営者・経営陣と面談し、  
受講者の担当職務と必要な業務スキルを確認します。

その職務に対応するAI活用スキルを整理し、  
**会社別のゴールと、受講者ごとの実務テーマを設定します。**

### 実務に近い題材で学びます

通常業務と区別したOFF-JT形式で、3時間×5回、計15時間実施します。

実際の業務に近い題材を使いながら、  
受講者自身が演習し、AIの出力を確認・修正する訓練として進めます。

研修の中で会社の業務を講師が代行するのではなく、  
**受講者自身がAIを使えるようになること**が目的です。

### 研修で身につけること

- 生成AIの特性と限界を理解する
- 情報をAIに渡せる形へ整理する
- 目的・条件・制約を言葉にする
- AIへの指示を改善する
- 文書・資料・説明案を作る
- 複数案を比較する
- 原資料と照合する
- 抜け漏れや誤りを確認する
- AIの出力を修正する
- 情報入力時の安全性を判断する
- AIに任せる部分と、人が判断する部分を分ける
- 自分の職務で次に試すテーマを整理する

### 受講後に目指す状態

**研修後も、自社でAIを使い続けられることを大切にしています。**

受講後は、AIを使って小さな業務課題を自力で前へ進められる状態を目指します。

会社には、

- AIを安全に使える人材
- 自社で試すAI活用テーマ
- 利用上の注意点・確認手順
- AI活用を継続するための考え方

が残るように設計します。

# 11. AIシステム・ツール受託開発

## 作れるかではなく、現場で使えるかを確かめてから作る。

AIでできそうに見えることでも、

そのためTriTransでは、最初から大きなシステムを作るのではなく、  
**既存業務と並行して、小さく検証することを重視します。**

### 対応例

**AIが下準備する。人が確認する。必要な部分だけ仕組みが支える。**

# 12. TriTrans Reviews

## 誤字脱字だけでは、終わりません。

営業資料、提案書、プレゼン資料、企画書。  
内容が正しくても、読み手が判断しにくければ、次には進みません。

TriTrans Reviewsでは、

- 何を伝える資料か
- 誰が読むのか
- 何を判断してほしいのか
- 根拠は足りているか
- 表現が強すぎないか
- 誤解される余地はないか
- 次に何を直すべきか

を確認します。

## Fact → Judgment → Trust

**事実を積む。判断を前へ進める。信頼を積層する。**

問題点を指摘するだけではなく、

# 13. 実際の支援から見えたこと

## AI活用では、「何を使うか」より先に見ることがあります。

TriTransでは、うまくいった結果だけを実績として並べるのではなく、  
支援の中でどのように考え、何を選び、何を選ばなかったかを大切にしています。

### CASE 01｜「AIをどこで使う？」ではテーマが出なかった

AIを使いたいという会社でも、  
「どこでAIを使いたいですか」と聞くだけでは具体的なテーマが出ないことがあります。

そこで、

- 時間がかかる仕事
- 繰り返しが多い仕事
- 間違えると怖い仕事
- 引き継ぎしにくい仕事

から確認すると、実際の業務テーマが見えてきました。

**AIから考えるのではなく、仕事の困り事から考える。**

---

### CASE 02｜「計算をAI化したい」を、そのまま自動化しなかった

相談は計算の自動化でした。

しかし業務を確認すると、  
先に整理すべきだったのは計算式ではなく、

**「何を判断するための計算なのか」**

という部分でした。

作業をそのまま自動化するのではなく、  
目的、判断条件、必要情報、人の確認まで分解してから設計しました。

---

### CASE 03｜「できそう」と「実証済み」を分けた

AIで扱えそうなテーマでも、  
最初から「できます」とは言いません。

既存の方法と並べて試し、  
実データで確認し、必要ならAI以外の方法も比較します。

**作れるかではなく、現場で使えるかを確かめてから作る。**

---

### CASE 04｜正しい指摘だけでは、レビューとして足りなかった

資料の問題点を正しく指摘しても、  
依頼者が「では何から直せばよいのか」と迷えば、仕事は前に進みません。

そこで、

- 優先順位
- 理由
- 修正方向
- 修正例

まで返す形へ改善しました。

**レビューは、正しさを示すためではなく、次の行動へ進めるために行う。**
